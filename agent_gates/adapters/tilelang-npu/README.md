# TileLang NPU adapter (host-local)

`tilelang-npu` builds a plain TileLang checkout on the host and runs its
Ascend examples on one authorized NPU. It is the host-local counterpart to
`tilelang-hivm` and `tilelang-hivm-npu`: no Docker, no container, no root, and
no HIVM compiler. Nothing here reaches the HIVM backend, so a PASS from this
Adapter says nothing about HIVM code generation.

| Gate | Operation | Inner / outer timeout |
| --- | --- | --- |
| `tilelang-npu-build` | `cmake` configure plus `cmake --build` (Ninja) of the checkout, then an import probe of the result | 3300 / 3600 s |
| `tilelang-npu-examples` | The pinned example tests through pytest with a JUnit report, after the build gate | 1500 / 1560 s |

## What the build gate proves

The checkout compiles from source against the interpreter the examples will
run under, and the result really is an Ascend-enabled TileLang: the gate reads
`libtilelang.so`, requires it to be a real object rather than a placeholder,
then asks that interpreter to import `tilelang` and report its own backend. The
import must resolve inside the tree under test, so a green flag from another
installed copy cannot stand in for this build.

It configures the tree every run instead of requiring an existing
`build/build.ninja`, which is where it deliberately differs from every other
Adapter here. A build tree is bound to the Python headers and the CMake that
produced it, and this host has produced trees that carried objects from a
different branch. Reusing one would let this gate report a build of sources it
never compiled. It never deletes a tree, so a re-run is incremental.

The build gate needs no device. `device: none` in the recipe is what lets it run
on a host whose cards are all busy.

## What the example gate proves

Real kernels run on the authorized card and their numerical assertions hold.
The gate runs a fixed list of example tests - by default vector addition,
RMSNorm and FP8 quantization - and parses the JUnit report for collected,
passed, failed and skipped counts. Zero collected tests, an all-skipped run, any
failure, a missing report and a timeout all fail; none of them can pass by
producing no observations.

The device id (`TILELANG_NPU_DEVICE_ID`) is a launch value, not a machine fact.
It is passed at invocation time, so a machine file can never imply a permanent
entitlement to a card.

## Machine configuration

The file is strict `NAME=value` data and is never executed or expanded. Keys are
`TILELANG_NPU_CANN_SETUP`, `_CONDA_SH`, `_CONDA_ENV`, `_CONDA_ENVS_PATH`,
`_PYTHON`, `_CMAKE_BIN`, `_BUILD_SUBDIR`, `_NINJA_JOBS` and `_EXAMPLE_TESTS`.

CANN is sourced before the conda environment, because the environment activation
provides the interpreter and the toolkit variables must already describe the
libraries it will load.

Size `TILELANG_NPU_NINJA_JOBS` to memory, not to cores. A translation unit in
this project peaks near 800 MiB; a job count sized to a many-core host can
exhaust a small memory cgroup and turn the build into forced reclaim and swap
thrash, which is far slower than a modest job count.

`TILELANG_NPU_CMAKE_BIN` exists because an existing tree is regenerated by the
CMake that wrote it, and environments on one host can ship different major
versions.

## Requirements and limits

CANN and torch_npu must agree. A toolkit whose torch_npu counterpart is not
installed still compiles and passes the build gate, but cannot initialize a
device, so the example gate reports a device failure rather than a numerical
one.

This is worth stating plainly because it was measured rather than assumed. Raw
ACL, with no torch loaded at all, returns aclrtSetDevice 0 on all three cards for
CANN 9.1.0 and 9.2.0, and 507033 on all three cards for 9.3.0-weekly. 9.3.0
requires torch_npu 2.13 and this host carries 2.10.0.post7, so a 507033 says the
toolkit and the wheel disagree - not that the build or the examples are wrong.
The same source, interpreter and device pass 9 of 9 examples under 9.1.0 and
9.2.0.

The example set is reviewed configuration rather than a glob, so the gate cannot
silently widen as examples are added.
